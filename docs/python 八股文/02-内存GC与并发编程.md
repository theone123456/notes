# 内存管理与并发编程（测开分水岭）

> 这一份文档是社招测开与初级测试的分界线：GIL、垃圾回收、进程线程协程，几乎每场面试都问。

## 一、GIL 全局解释器锁（必考）

### 1. 是什么

CPython 解释器中的一把全局互斥锁：**同一时刻只允许一个线程执行 Python 字节码**。即使多核 CPU，多线程也无法并行执行 Python 代码。

### 2. 为什么存在

CPython 用**引用计数**做内存管理，计数增减非线程安全。GIL 是用一把大锁保护所有对象引用计数的最简单方案（历史设计权衡，而非语言规范）。

### 3. 影响（面试标准答法）

| 任务类型 | GIL 影响 | 推荐方案 |
|---|---|---|
| CPU 密集（计算、压缩、加密） | 多线程无加速，甚至更慢（切换开销） | **多进程** multiprocessing |
| IO 密集（网络请求、读写文件、sleep） | IO 阻塞时释放 GIL，多线程有效 | **多线程** threading 或 **协程** asyncio |

**GIL 释放时机**：阻塞 IO、`time.sleep()`、C 扩展中手动释放（如 numpy 大量运算时释放 GIL）。

**绕过方式**：多进程、把热点代码下沉到 C 扩展、Python 3.13 的 free-threading 实验版（no-GIL，了解即可）。

### 4. 面试追问

- "为什么 Python 多线程跑 CPU 计算比单线程还慢？" -> 线程切换 + GIL 争抢开销
- "既然有 GIL，还需要加锁吗？" -> **需要**，见下文

## 二、垃圾回收（必考）

### 1. 三件套

| 机制 | 原理 | 特点 |
|---|---|---|
| **引用计数**（主力） | 每个对象记录被引用数，归零立即回收 | 即时、简单；**无法处理循环引用**；维护计数有开销 |
| **标记-清除** | 从根对象（全局、栈帧）出发遍历标记可达对象，清除不可达 | 解决循环引用；需要暂停（stop-the-world） |
| **分代回收** | 对象按存活时间分 0/1/2 三代，新生代回收频繁、老年代回收少 | 基于弱代假说：多数对象朝生夕死；阈值默认 (700, 10, 10) |

### 2. 循环引用示例

```python
a = []
b = []
a.append(b)      # a -> b
b.append(a)      # b -> a   引用计数各为 1（被对方引用），永远不会归零
del a, b         # 只能靠标记-清除回收
```

### 3. gc 模块

```python
import gc
gc.collect()                  # 手动触发回收，返回清除对象数
gc.get_threshold()            # (700, 10, 10)
gc.disable()                  # 关闭自动 GC（性能敏感场景/已知无循环引用）
```

### 4. 内存泄漏排查（测开加分项）

常见泄漏源：
- 全局容器（缓存 dict/list）只增不减
- 闭包/长生命周期对象持有大对象引用
- `__del__` 里抛异常或循环引用带 `__del__`（老版本无法回收）
- 被遗漏的定时器、回调、线程未结束

排查工具：`tracemalloc`（快照对比定位增长点）、`objgraph`（对象引用关系图）、`gc.get_referrers(obj)`（查谁引用了它）、`sys.getsizeof()`。

## 三、进程、线程、协程（必考）

### 1. 三者对比（必背）

| 维度 | 多进程 | 多线程 | 协程 |
|---|---|---|---|
| 切换开销 | 大（页表、缓存刷新） | 中（内核切换上下文） | 极小（用户态切换） |
| 内存 | 独立地址空间，隔离好 | 共享进程内存 | 同一线程内 |
| 通信 | Queue/Pipe/共享内存/文件 | 共享变量 + 锁 | 天然同线程，靠 channel/await |
| GIL | 不受影响（真并行） | 受限 | 不受影响 |
| 崩溃影响 | 一个进程挂不影响其他 | 一个线程崩可能拖垮进程 | 同线程 |
| 适用 | CPU 密集 | IO 密集 + 需要利用多核时的并发 | 超高并发 IO（万级连接） |
| 数据安全 | 天然隔离 | 需要锁 | 单线程内顺序执行，通常无需锁 |

### 2. threading

```python
import threading

t = threading.Thread(target=work, args=(1,), daemon=True)
t.start()          # 启动线程（t.run() 只是普通函数调用，不开线程！）
t.join(timeout=5)  # 等待结束
```

- `daemon=True`：守护线程，主线程退出时直接被杀（适合后台采集/心跳）
- `start()` vs `run()`：**经典笔试题**，run() 是同步调用不会新建线程

**为什么 GIL 下还要加锁？**
GIL 保证单条字节码原子，但 `i += 1` 是三条字节码（LOAD / ADD / STORE），线程可在中间被切走：

```python
counter = 0
def unsafe():
    global counter
    for _ in range(100000):
        counter += 1          # 两个线程各加 10 万次，结果 < 200000

def safe(lock):
    global counter
    for _ in range(100000):
        with lock:
            counter += 1      # 正确 200000
```

### 3. 锁全家桶

| 同步原语 | 用途 |
|---|---|
| `Lock` | 互斥锁，一把钥匙 |
| `RLock` | 可重入锁，同一线程可多次 acquire（避免自锁死） |
| `Semaphore(n)` | 允许 n 个线程同时进入（限流，压测并发数控制） |
| `Event` | 事件标志位，`wait()` 阻塞直到 `set()`（起跑信号、优雅退出） |
| `Condition` | 条件变量，wait/notify（生产者消费者） |
| `queue.Queue` | 线程安全队列，自带锁（生产者消费者首选） |

**死锁四条件**：互斥、持有并等待、不可剥夺、循环等待。避免：统一加锁顺序、使用超时 `lock.acquire(timeout=)`。

### 4. multiprocessing

```python
from multiprocessing import Pool

def cpu_task(n):
    return sum(i * i for i in range(n))

if __name__ == '__main__':            # Windows/spawn 模式必须保护入口
    with Pool(processes=4) as pool:
        results = pool.map(cpu_task, [10**6] * 8)
```

进程间通信：`Queue`（安全传对象）、`Pipe`（双端管道）、`Manager`（共享 dict/list）、`Value/Array`（共享内存）。

### 5. concurrent.futures（工程推荐写法）

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import requests

def hit(url):
    r = requests.get(url, timeout=5)
    return r.status_code, r.elapsed.total_seconds()

with ThreadPoolExecutor(max_workers=50) as pool:
    futures = {pool.submit(hit, 'https://example.com'): i for i in range(200)}
    for fut in as_completed(futures):
        print(fut.result())          # 谁先完成先处理谁
```

- 线程池 -> IO 密集；进程池 `ProcessPoolExecutor` -> CPU 密集
- `pool.map`：保序返回结果，写法最简单
- **测开场景**：这就是一个 200 并发的简易压测脚本

### 6. 协程 asyncio

```python
import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as resp:
        return resp.status

async def main():
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, f'https://example.com/{i}') for i in range(100)]
        results = await asyncio.gather(*tasks)     # 并发执行全部任务
        print(results)

asyncio.run(main())
```

- `async def` 定义协程函数，调用返回协程对象（不执行）
- `await`：让出控制权，等待结果（等待期间事件循环跑其他任务）
- 事件循环（event loop）在单线程内调度大量协程，切换是用户态的，成本远低于线程
- 单线程内执行 -> 无需锁；但**不能有阻塞调用**（`time.sleep`/`requests` 会卡死整个循环，要用 `asyncio.sleep`/`aiohttp`）

**协程 vs 多线程（面试标准答法）**：都能做 IO 并发。线程由 OS 内核调度、切换开销微秒级、有栈内存（默认可达 MB 级）；协程由程序自己调度、切换纳秒级、内存 KB 级，单机可开十万级协程，适合超高并发 IO；但协程生态要求全链路 async。
