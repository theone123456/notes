# 网络、数据库与设计模式

> 测开面试的网络/数据库部分不会问太深，但状态码、SQL 手写、索引、Redis 三兄弟、单例工厂是必考级别。

## 一、网络基础

### 1. TCP vs UDP

| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠（确认、重传、排序） | 尽力交付 |
| 速度/开销 | 慢、开销大 | 快、开销小 |
| 场景 | HTTP/SSH/数据库连接 | DNS、视频直播、心跳 |

### 2. 三次握手与四次挥手（必考）

**三次握手（建连）**：客户端 SYN -> 服务端 SYN+ACK -> 客户端 ACK。
> 为什么三次？双方都要确认"我能发你能收"；两次无法防止历史失效连接请求（旧的 SYN 迟到）造成资源浪费。

**四次挥手（断连）**：主动方 FIN -> 被动方 ACK -> 被动方 FIN -> 主动方 ACK。
> 为什么四次？被动方收到 FIN 后可能还有数据没发完，ACK 先回、发完数据再 FIN，所以中间两步不能合并。主动方最后 TIME_WAIT 等 2MSL，确保对方收到了最后的 ACK。

### 3. HTTP 必考

**状态码（必须秒答）**：

| 类别 | 常见 | 含义 |
|---|---|---|
| 2xx | 200 / 201 / 204 | 成功 / 创建成功 / 无内容 |
| 3xx | 301 / 302 / 304 | 永久重定向 / 临时重定向 / 协商缓存命中 |
| 4xx | 400 / 401 / 403 / 404 / 429 | 参数错误 / **未认证** / **已认证但无权限** / 不存在 / 请求过多 |
| 5xx | 500 / 502 / 503 / 504 | 服务器内部错误 / **网关收到无效响应** / 服务不可用 / **网关超时** |

测开追问：502 和 504 的区别？-> 502 是后端返回了无效响应或直接断开；504 是后端在超时时间内没响应。

**GET vs POST**：GET 参数在 URL、长度受限、可缓存、幂等；POST 在 body、适合敏感/大量数据。本质区别：GET 是获取（幂等），POST 是提交（非幂等）。

**RESTful**：用 HTTP 方法表达语义——GET 查、POST 增、PUT 全量改（幂等）、PATCH 部分改、DELETE 删；URL 用名词复数 `/users/1/orders`。

**HTTPS**：HTTP + TLS。握手一句话：客户端验证服务端证书、协商对称密钥，之后对称加密通信（非对称只交换密钥，对称加密数据）。

**Cookie / Session / Token(JWT)**：Cookie 存客户端；Session 存服务端（靠 Cookie 里的 sessionId 关联，服务端有状态）；JWT 自包含签名信息存客户端，服务端无状态、适合分布式。

### 4. requests 深入（测开重点）

```python
import requests
from requests.adapters import HTTPAdapter

session = requests.Session()                  # 复用 TCP 连接、统一携带 headers/cookies
session.headers.update({'Authorization': 'Bearer xxx'})

resp = session.post(
    'https://api.example.com/login',
    json={'user': 'a', 'pwd': 'b'},           # json= 自动序列化 + Content-Type: application/json
    timeout=(3, 10),                          # (连接超时, 读取超时)，必须显式设置！
)
resp.status_code / resp.json() / resp.text / resp.elapsed.total_seconds()

# 网络层自动重试（连接失败级别）
adapter = HTTPAdapter(max_retries=3)
session.mount('https://', adapter)

# 异常处理
try:
    resp = session.get(url, timeout=5)
    resp.raise_for_status()                   # 4xx/5xx 抛 HTTPError
except requests.Timeout:
    ...
except requests.ConnectionError:
    ...
except requests.RequestException as e:        # 所有 requests 异常的基类，兜底
    ...
```

**必考对比**：
- `json=` vs `data=`：json= 发 JSON 体（自动设头）；data= 发表单（x-www-form-urlencoded）或原始字符串
- Session vs requests.get：Session 复用连接池、保持 cookies、统一配置
- timeout 单值 vs 元组：单值同时限制连接和读取；元组分别指定

**同族库**：httpx（同步+异步、HTTP/2）、aiohttp（纯异步）、urllib（标准库，繁琐）。

## 二、MySQL（必考）

### 1. 手写高频 SQL

```sql
-- 1. join：查每个学生的姓名和成绩（内连接）
SELECT s.name, sc.score
FROM students s
INNER JOIN scores sc ON s.id = sc.student_id;

-- 2. left join + 统计：每个部门的人数（没人的部门也要显示 0）
SELECT d.dept_name, COUNT(e.id) AS cnt
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
GROUP BY d.dept_name;

-- 3. 分组过滤：平均分大于 80 的班级（WHERE 在分组前、HAVING 在分组后）
SELECT class_id, AVG(score) AS avg_score
FROM scores
GROUP BY class_id
HAVING AVG(score) > 80;

-- 4. 第 N 高（去重 + 排序 + 偏移）
SELECT DISTINCT salary
FROM employee
ORDER BY salary DESC
LIMIT 1 OFFSET 1;                 -- 第二高；没有则返回空，经典题是配 IFNULL

-- 5. 条件聚合
SELECT
  SUM(CASE WHEN status = 'success' THEN 1 ELSE 0 END) AS ok_cnt,
  SUM(CASE WHEN status = 'fail' THEN 1 ELSE 0 END) AS fail_cnt
FROM api_logs;
```

**执行顺序**：FROM -> JOIN -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY -> LIMIT（WHERE 不能用聚合函数的原因）。

### 2. 索引（必考）

- **为什么 B+ 树**：非叶子节点不存数据只存索引 -> 单页放更多键 -> 树更矮（3 层撑千万级）；叶子节点双向链表 -> 范围查询/排序友好。对比哈希索引不支持范围，B 树数据分散在所有节点。
- **聚簇 vs 二级索引**：主键索引叶子存整行（聚簇）；二级索引叶子存主键值 -> 查非索引列需要**回表**（先查二级拿主键，再查主键树）
- **覆盖索引**：查询的列全在索引里，免回表（`SELECT id, name` 且有 (id,name) 联合索引）
- **最左前缀原则**：联合索引 (a,b,c) 只能命中 a / a,b / a,b,c 开头的查询；`b=1` 单独用不上
- **索引失效场景**：对索引列用函数/运算、隐式类型转换（字符串列传数字）、`LIKE '%xx'` 前缀通配、OR 连接非索引列、违反最左前缀

### 3. 事务（必考）

- **ACID**：原子性（undo log）、一致性（目的）、隔离性（锁+MVCC）、持久性（redo log）
- **隔离级别与并发问题**：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| 读未提交 | 有 | 有 | 有 |
| 读已提交（RC） | 无 | 有 | 有 |
| **可重复读（RR，InnoDB 默认）** | 无 | 无 | 基本无（MVCC + 间隙锁） |
| 串行化 | 无 | 无 | 无 |

一句话区分：脏读=读到别人未提交的；不可重复读=两次读同一行值不同（别人 update）；幻读=两次读行数不同（别人 insert）。

### 4. 其他高频

- InnoDB vs MyISAM：事务/行锁/外键 vs 无事务只有表锁（读多写少、COUNT 快）
- char(10) 定长 vs varchar(10) 变长（额外 1-2 字节长度）
- `DELETE` 逐行删可回滚 / `TRUNCATE` 重建表不可回滚重置自增 / `DROP` 连表结构一起删
- 深分页优化：`LIMIT 1000000, 10` 慢 -> 先查 id 再 join（延迟关联）或游标（where id > last_id）

### 5. pymysql 与 SQL 注入（测开必考）

```python
import pymysql

conn = pymysql.connect(host=..., user=..., password=..., database=..., charset='utf8mb4')
cursor = conn.cursor()

# 危险写法：拼接 SQL，输入 ' OR '1'='1 即可绕过
cursor.execute(f"SELECT * FROM users WHERE name = '{name}'")

# 正确写法：参数化查询，驱动负责转义
cursor.execute("SELECT * FROM users WHERE name = %s", (name,))

conn.commit() / conn.rollback()
```

> 为什么参数化有效：SQL 结构与数据分离，用户输入永远只被当作**数据**，不参与 SQL 语法解析。

## 三、Redis（常考）

### 1. 五大类型与应用场景

| 类型 | 场景 |
|---|---|
| String | 缓存对象、计数器、分布式锁（SETNX） |
| Hash | 对象字段级缓存（用户信息） |
| List | 消息队列、最新列表 |
| Set | 去重、共同好友（交并集）、抽奖 |
| ZSet | 排行榜、延迟队列（按 score 排序） |

### 2. 缓存三兄弟（必考）

| 问题 | 定义 | 对策 |
|---|---|---|
| **穿透** | 查询**不存在**的 key，每次都打到 DB | 缓存空值（短 TTL）/ 布隆过滤器 / 参数校验 |
| **击穿** | 某个**热点** key 过期瞬间大量请求打 DB | 互斥锁重建 / 热点 key 永不过期 |
| **雪崩** | **大量** key 同时过期或 Redis 宕机 | TTL 加随机值 / 高可用集群 / 限流降级 |

### 3. 其他要点

- **为什么快**：内存操作 + 单线程无锁竞争 + IO 多路复用（epoll）+ 高效数据结构
- **持久化**：RDB（定时快照，恢复快、可能丢数据）vs AOF（追加写命令，更安全、文件大）；4.0+ 混合持久化
- **过期删除**：惰性删除 + 定期抽查
- 缓存与 DB 一致性：先更新 DB 再删缓存（Cache Aside），配延迟双删（能讲出取舍即可）

## 四、设计模式（测开必会三个）

### 1. 单例模式（手写题级别，详见 05 文档）

保证一个类只有一个实例。四种写法：`__new__`、装饰器、元类、模块天然单例（import 只执行一次）。多线程环境需要加锁（双重检查）。

```python
import threading

class Singleton:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:                    # 第一次检查（无锁快速路径）
            with cls._lock:
                if cls._instance is None:            # 第二次检查（防止排队重复创建）
                    cls._instance = super().__new__(cls)
        return cls._instance
```

### 2. 工厂模式

```python
class TestApiClient: ...
class PreprodApiClient: ...

def create_client(env: str):
    factories = {'test': TestApiClient, 'preprod': PreprodApiClient}
    if env not in factories:
        raise ValueError(f'未知环境: {env}')
    return factories[env]()                # 调用方不关心具体类怎么创建
```

测开场景：按环境/按平台创建客户端、按报告类型创建生成器。好处：创建逻辑集中、新增类型只改一处（对扩展开放）。

### 3. PO 模式（Page Object，自动化专属）

把页面/接口封装成对象类：定位器/URL 与操作方法内聚，用例只调用方法。UI 变了只改 PO 类，用例不动。（api_framework 的 apis/ 层就是接口版 PO。）

### 4. 一句话储备（防追问）

- 策略模式：封装一组可互换算法（不同的失败重试策略、数据生成策略）
- 观察者模式：状态变化通知订阅者（测试完成后同时通知邮件/钉钉/企微）
- 代理模式：控制对象访问（懒加载、鉴权）——装饰器是它的语言级实现
