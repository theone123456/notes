## Step 拆解

### Step 1 · 预训练：知识从哪来（类型：概念）

**前置依赖**：Day 4 的 token 概念（预训练处理的基本单位就是 token）；Day 6 的"概率接龙机器"比喻（预训练就是把这件事练到极致）

**做什么**：
- 学习预训练（pre-training）做什么：在海量文本（万亿 token 级）上训练模型做一件事——**预测下一个 token**（next token prediction）
- 理解为什么这个简单目标能"顺便"学到知识、语法、推理模式（为了预测得准，不得不理解上下文）
- 建立量级直觉：数据规模（TB 级文本）、算力成本（千万美元级）——为什么预训练是少数大厂的游戏，个人和大多数公司只能从训练好的模型起步
- 认识 base model（基座模型）的行为特征：只会"续写"、不会"对话"——直接问它问题，它可能续写出更多问题而不是给出回答（这是 Step 2 要解决的问题）

**参考资料**：
- 可问 AI："大模型的预训练具体在做什么？为什么预测下一个 token 就能学到知识？"
- 可问 AI："什么是 base model？拿它直接对话会是什么体验，为什么？"
- 可问 AI："预训练一次大概要多少数据、多少算力？为什么小公司不自己预训练？"

**检查点**：
- 能说出预训练的目标（预测下一个 token）和处理单位（token）
- 能解释 base model 为什么"会接龙但不会对话"
- 能说出预训练的量级为什么决定了它是大厂的游戏

**产出**：
- 笔记：记入 readme.md 的训练三阶段节（预训练小节）

### Step 2 · 微调（SFT）：从会接龙到会对话（类型：概念）

**前置依赖**：Step 1 的 base model 概念（微调解决的就是"不会对话"）

**做什么**：
- 学习监督微调 SFT（Supervised Fine-Tuning）：用人工标注的"指令 → 高质量回答"对继续训练 base model，教它**按指令回答**而不是续写
- 理解 SFT 前后的行为变化：输入"写一首关于秋天的诗"，从"续写出更多要求"变成"真的写诗"
- 了解微调的适用场景（在通用模型上补短板）：固定输出格式、特定领域风格术语——以及它与 RAG 的分界：**微调改"行为/风格"，RAG 补"知识/事实"**（阶段 3 深挖，今天记住这条分界线即可）
- 了解级扫一眼：全参微调 vs LoRA 等高效微调——知道 LoRA"只训小附件、不动大模型"的思想即可，不展开

**参考资料**：
- 可问 AI："SFT 是怎么让只会续写的 base model 变成会对话的？训练数据长什么样？"
- 可问 AI："什么情况该微调、什么情况该用 RAG 或提示词？边界在哪？"
- 可问 AI："LoRA 这类高效微调的思路是什么？为什么不全参数微调？"

**检查点**：
- 能说出 SFT 的训练数据形态（指令-回答对）和它改变的行为（续写 → 应答）
- 能说出至少 2 个微调的适用场景，以及"改行为"与"补知识"的分界
- 能回答"个人开发者为什么几乎不做预训练、但可以做微调"（量级差多少）

**产出**：
- 笔记：记入 readme.md 的训练三阶段节（微调小节）

### Step 3 · 对齐：回答得更好、更安全（类型：概念）

**前置依赖**：Step 2（对齐建立在"已经会对话"的模型上）

**做什么**：
- 理解对齐（alignment）要解决的问题：SFT 后模型"会回答"，但回答未必**符合人类偏好**——可能啰嗦、有害、不诚实
- 学习 RLHF（人类反馈强化学习）的核心思想（了解级，不碰数学）：
  1. 人类对同一问题的多个回答排序（偏好数据）
  2. 训练奖励模型（reward model）学会给回答打分
  3. 用强化学习让模型往高分方向优化
- 建立三阶段全景（Step 1-3 的收口）：**预训练学到能力 → SFT 学会对话 → 对齐变得好用安全**
- 用对齐视角回看日常观察：模型为什么普遍拒答有害请求？为什么回答爱分点、语气客气？——都是对齐的产物

**坑位提示**：
- 别把"微调"和"对齐"混为一谈：SFT 是**模仿示范**（学人怎么答），对齐是**优化偏好**（学人觉得什么更好）——面试常考的区分
- RLHF 理解思想即可；DPO 等变体知道名字即可，不深入

**参考资料**：
- 可问 AI："RLHF 的大致流程是什么？为什么说它教的是'偏好'而不是'答案'？"
- 可问 AI："模型的礼貌、拒答、分点作答这些习惯是哪个阶段给的？"

**检查点**：
- 能用自己的话说清三阶段各自解决什么问题（一条流水线：能力 → 对话 → 偏好）
- 能说出 SFT 和对齐的本质区别（模仿示范 vs 优化偏好）
- 能举出 2 个日常使用中"对齐的痕迹"

**产出**：
- 笔记：记入 readme.md 的训练三阶段节（对齐小节 + 三阶段总结表）

### Step 4 · 三阶段 × 已学现象连线（类型：思考）

**前置依赖**：Step 1-3 的三阶段概念；Day 2-6 的概念（system prompt、token、上下文窗口、幻觉、temperature）

**做什么**：
- 把阶段 0 学过的现象逐个归属到训练阶段，理解"我观察到的 API 行为，是哪个阶段的产物"：
  1. **system prompt 能改变行为** → 对齐（模型被教会了听从系统级指令）
  2. **幻觉不可避免** → 预训练（目标是概率预测，没有事实校验环节）
  3. **temperature 调整有效** → 预训练（模型输出的是概率分布，采样只是从中挑选的方式）
  4. **知识有截止时间** → 预训练（数据集固定，训练完就"定格"）
  5. **按 token 计费、上下文有窗口** → 预训练架构与成本的直接映射（transformer 处理的单位、注意力的开销）
- 整理成一张"现象 → 归属阶段 → 一句话解释"对照表写入 readme.md
- 补两条前瞻连线（给后续阶段铺路）：RAG 缓解幻觉（Day 6）对应"预训练知识定格"这个成因；Function Calling 依赖的是对齐练出来的指令遵循——今天埋的线，阶段 1-3 会兑现

- 能说出"为什么 API 调用层面的种种现象，根子大多在训练阶段"
