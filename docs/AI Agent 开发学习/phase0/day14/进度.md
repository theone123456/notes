### Step 2 · GitHub 建仓与首次 push（类型：编码）

**前置依赖**：Step 1（docs/ 已提交，仓库内容定型后再 push，避免刚 push 又补提交）

**做什么**：
- GitHub 上新建空仓库（建议名 `llm_client`，公开）——**不勾任何初始化选项**（不建 README / .gitignore / license），远程一旦凭空多出提交，本地 push 就会被拒（Day 12 已定的决策）
- 本地 `git remote add origin <仓库地址>`，然后 `git push -u origin main`（`-u` 建立跟踪，以后直接 `git push`）
- push 后复核三件事：GitHub 页面能看到提交历史；线上文件清单与本地 `git ls-files` 一致；**确认 `.env` / `history.json` 不在远程**——push 之后仓库公开可见，性质与本地完全不同
- 可选收尾：GitHub 仓库页补 About 一句话描述

**坑位提示**：
- 不小心勾了初始化选项导致 push 被拒：补救是 `git pull --rebase` 合并远程那次提交——今天知道有这条退路即可
- 首次 push 需要认证：HTTPS 走 Personal Access Token，SSH 走 key，按 GitHub 提示配置

**检查点**：
- 远程仓库有完整提交历史，文件与本地一致，无敏感文件
- 能说出"为什么建仓不勾任何初始化选项"

**产出**：
- GitHub 远程仓库 + 首次 push
