## Step 拆解

### Step 1 · usage 字段全家福与计费公式（类型：概念）

**前置依赖**：Day 4 readme.md 的「按 token 计费」一节（输入/输出单价不同、prefill vs decode、reasoning_tokens 按输出价计费）

**做什么**：
- 复习 usage 三件套：`prompt_tokens` / `completion_tokens` / `total_tokens`（Day 2 首次接触，Day 4 学过计费逻辑），今天要把它从"看得懂"变成"用得上"
- 认识两个 details 子字段（估算精度全靠它们）：
  - `usage.prompt_tokens_details.cached_tokens`：命中前缀缓存的部分，按**缓存命中价**计费（远低于标准输入价）
  - `usage.completion_tokens_details.reasoning_tokens`：模型思考消耗的 token，**已计入 completion_tokens、按输出价计费**
- 查 glm-5.3 在火山方舟的单价（Step 3 写代码要用）。参考价（元/百万 token，与 Z.ai 官方一致）：**输入 8.0 / 输出 28.0 / 缓存命中输入 2.0**。方舟价格页可能未及时列出 glm-5.3 行，**以方舟控制台计费明细为准**，价格会调整
- 把计费公式写成一行（这就是 Step 3 的实现规格）：

```text
费用（元） = 输入单价 × prompt_tokens / 1e6 + 输出单价 × completion_tokens / 1e6
```

- 了解一个 glm-5.3 特有的坑：**思考模式强制开启**（thinking 关不掉，reasoning_effort 只有 low/high/max 三档且默认 max），思考 token 全按输出价计费--这正是 Day 4 实验"completion_tokens 远大于存回 assistant 内容"的成因，今天用 `reasoning_tokens` 字段实证闭环
- 记住最常见的新手错误：**计价单位是"元/百万 token"，token 数要除以 1_000_000 再乘单价**，忘了除就是百万倍的账单

**参考资料**：
- 火山方舟文档「模型价格」（docs.volcengine.com，文档 ID 1544106）或方舟控制台的计费明细页
- Day 4 readme.md 的「按 token 计费」「多轮对话的复利计费」两节

**检查点**：
- 能默写计费公式，并说出为什么输入输出要分开乘单价
- 能回答"reasoning_tokens 藏在哪个字段、计入哪个口径、按哪个单价计费"
- 手算：一次调用输入 1000 token、输出 2000 token 花多少钱（预期：0.008 + 0.056 = 0.064 元）

**产出**：
- 笔记：记入 readme.md 的概念节

### Step 3 · 成本估算方法（类型：编码）

**前置依赖**：Step 2 的累计器

**做什么**：
- 类内加价格表常量（元/百万 token），结构用 dict 方便以后多模型扩展：

```python
PRICES = {"glm-5.3": {"input": 8.0, "output": 28.0}}  # 以控制台实际价格为准
```

- 实现 `estimate_cost()`：用累计 token 按公式算钱。金额很小，格式化保留 6 位小数（如 0.000064 元），也可顺手换算成"1 分钱能聊几轮"这类直觉表述
- 实现 `report()`：打印总输入/输出 token、成功调用次数、估算费用--这就是完成标志要的"会话结束能打印"
- 可选进阶：读取 `prompt_tokens_details.cached_tokens`，命中部分按缓存价 2.0 元计；字段缺失就按 0 处理

**检查点**：
- 单轮对账：拿一次已知 usage 的调用手算费用，与 `estimate_cost()` 输出一致
- 金额量级合理：一轮中文闲聊几千 token，费用应在 0.001~0.01 元量级；算出几块钱说明忘了除 1e6

**产出**：
- 文件：`llm_client_with_usage.py` 更新（自写，写完贴给 AI review）
