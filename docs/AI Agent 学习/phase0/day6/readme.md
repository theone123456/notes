# Day 6 学习笔记：幻觉与模型格局

> 核心命题：幻觉是概率预测的必然副产物--模型不"知道"事实，只预测最可能的文字序列，理解成因才能对症缓解
> 产出脚本：`hallucination_experiment.py`

## 幻觉的定义与本质

> 来源：LLM 基础概念 · 目的：理解幻觉是什么、为什么会产生，建立"模型是概率预测器而非知识库"的核心直觉

**幻觉（hallucination）**：模型生成看似合理但实际不正确、无依据或虚构的内容。

关键特征：内容语法通顺、逻辑看似合理、语气自信，但事实错误或完全是编造的。模型不会标注"我不确定"。

### 幻觉 vs 说谎：不是在骗你，而是不知道什么是"真"

| 对比维度 | 人类说谎 | LLM 幻觉 |
|---|---|---|
| 意图 | 有意欺骗，知道真相但说假的 | 无意图，没有"说谎"的概念 |
| 知识状态 | 知道正确答案，故意说错的 | 不存在"知道正确答案"这一步，不知道自己在"编" |
| 自我认知 | 有"我知道 / 不知道"的判断力 | 无法区分"自己知道的"和"自己生成的" |
| 纠正 | 被戳穿后会承认（心虚） | 无法"戳穿"，它"信"了自己编的内容 |

> 一句话：幻觉不是模型在"骗你"，而是模型根本不具备"真 / 假"的概念--它只是在做概率预测。

### LLM 是"概率接龙机器"

传统软件和 LLM 回答问题的机制完全不同：

```text
传统软件 / 数据库的问答方式：
  用户提问 -> 查询知识库 -> 找到匹配记录 -> 返回结果
                                     └-> 找不到 -> 返回"查不到"

LLM 的问答方式：
  用户提问 "XX是什么？"
    ↓
  拼接为上下文，送入模型
    ↓
  模型预测：训练数据中，"XX是什么？"后面通常跟着什么样的文字？
    ↓
  逐 token 生成概率最高的文字序列
    ↓
  训练数据中见过类似问题 -> 大概率生成正确答案
  训练数据中没见过     -> 仍生成"看起来像答案"的文字（幻觉）
```

**核心**：模型不"查询"知识，而是"生成"概率最高的文字序列。它不具备三种能力：

| 缺失的能力 | 说明 | 后果 |
|---|---|---|
| 知识验证 | 无法判断自己生成的内容是否正确 | 编造的内容被当作事实输出 |
| 来源追踪 | 不知道哪些内容来自训练数据、哪些是自己推测的 | 无法区分"确信"和"猜测" |
| 不确定性标注 | 不会主动说"我不确定"或"这可能不对" | 所有内容都以同样自信的语气输出 |

### 为什么幻觉内容看起来很"合理"

幻觉之所以危险，是因为它**看起来完全正常**：

```text
原因：模型优化的是"文字序列的概率"，不是"事实的正确性"

训练数据 = 人类写的连贯文本（书籍、文章、对话）
  ↓
模型学到的 = "什么样的文字接在一起最像人话"
  ↓
即使内容是编的，语法一定通顺、逻辑看似自洽
  ↓
因为模型生成的是"最像答案的答案"，不是"最正确的答案"
```

| 维度 | 模型优化目标 | 实际效果 |
|---|---|---|
| 语法正确性 | 是（训练数据都是语法正确的文本）| 几乎不会出现语法错误 |
| 逻辑连贯性 | 是（训练数据中文字前后有关联性）| 论述看起来有条理 |
| 事实正确性 | **否**（概率预测不包含"事实校验"步骤）| 可能编造看似合理的事实 |

> 一句话：模型优化的是"看起来对"，不是"事实上对"--这正是幻觉难以识别的原因。

**关键认知**：

1. **幻觉是概率预测的副产物，不是有意欺骗**：模型没有"说谎"的意图，它不具备"真 / 假"的概念，只是在预测最可能的下一个 token
2. **幻觉 vs 说谎的本质区别在于知识状态**：说谎者知道真相但故意说假，幻觉者根本不存在"知道真相"这一步
3. **LLM 是"概率接龙机器"而非"知识查询引擎"**：它不查询事实，而是生成概率最高的文字序列，训练数据见过的问题恰好能答对，没见过的就编
4. **幻觉内容看起来合理**：模型优化的是"文字序列的概率"而非"事实的正确性"，所以编造的内容语法通顺、逻辑看似自洽
5. **模型缺失三种能力导致幻觉无法自检**：知识验证、来源追踪、不确定性标注--没有这些能力，模型无法知道自己"在编"

> 一句话：幻觉不是 bug，是"概率接龙"机制的必然结果--模型追求"最像答案的回答"，而非"最正确的回答"。

### 本节记住五件事

1. 幻觉 = 模型生成看似合理但实际不正确 / 虚构的内容，语气自信，不标注不确定性
2. 幻觉不是"说谎"：说谎者知道真相但故意说假，幻觉者不存在"知道真相"这一步
3. LLM 是"概率接龙机器"：不查询知识库，而是预测最可能的文字序列，没见过的问题照样"接"出一套"像答案"的话
4. 模型缺失三种能力：知识验证、来源追踪、不确定性标注--所以无法自检幻觉
5. 幻觉内容看起来合理：模型优化"看起来对"而非"事实上对"，这正是幻觉难以识别的原因

## 幻觉的成因

> 来源：LLM 基础概念 · 目的：理解幻觉为什么会产生、有哪些具体成因，为"对症缓解"打基础

### 根因：概率预测本质

所有幻觉成因的共同根在于：**模型的生成流水线中没有"事实校验"步骤**。

```text
传统软件 / 数据库：
  用户提问 -> 查询知识库 -> 有结果 -> 返回
                            └-> 无结果 -> 返回"查不到"

LLM：
  用户提问 -> 拼接上下文 -> 逐 token 预测概率最高的文字 -> 输出
                                       ↑
                                  没有这一步：事实校验
```

模型没有"我不知道"的状态--它永远会生成文字，区别只在于生成的文字碰巧对不对。如果训练数据中有正确答案 -> 大概率答对；如果没有 -> 仍然生成"最像答案"的文字（幻觉）。

> 一句话：幻觉不是 bug，是"概率预测"机制的必然副产物--生成流水线里没有事实校验步骤，模型永远会输出。

### 具体成因

| 成因 | 机制 | 举例 |
|---|---|---|
| **概率预测本质（根因）** | 模型不查询事实，只生成概率最高的文字，没有事实校验步骤 | 问虚构问题，模型仍生成"看起来像答案"的文字 |
| **训练数据截止时间** | 知识有训练时的时效边界，截止后的新事件模型不知道，但仍可能"猜"一个看似合理的答案 | 模型训练截止 2025 年 1 月，2025 年 6 月某公司换了 CEO，问"现在 CEO 是谁"，模型自信地回答旧 CEO 的名字 |
| **训练数据质量问题** | 训练数据中的错误信息、偏见、噪声被模型"学到"并复现 | 训练数据中某百科词条有错误，模型把这个错误当作事实输出 |
| **长尾知识（冷门领域）** | 冷门领域训练数据稀少，模型先验弱，概率分布平缓，更容易编造 | 问一个非常冷门的历史人物，模型编造其生平 |
| **prompt 措辞引导** | 提问方式暗示模型"应该知道"，诱发编造 | "请详细介绍张三的代表作"比"你知道张三吗"更容易诱发幻觉 |

### 长尾知识 vs 长尾 token：容易混淆的概念

```text
长尾知识（幻觉的成因）：
  冷门领域在训练数据中出现次数少 -> 模型对这个领域的"先验"弱
  -> 概率分布平缓（没有哪个 token 概率明显高）
  -> 更容易生成"看起来像答案但实际编造"的内容

长尾 token（这是 temperature 的问题，不是幻觉的成因）：
  低概率 token 在高 temperature 下被选中 -> 这是采样随机性
  -> 可能导致乱码或偏离主题，但不是幻觉的根因
```

> 一句话：长尾知识是"训练数据不够导致模型先验弱"，长尾 token 是"采样时低概率词被选中"--前者是幻觉成因，后者是 temperature 效果。

### 为什么幻觉不可避免

幻觉的"不可避免"源于模型架构层面的三个事实：

| 事实 | 说明 | 后果 |
|---|---|---|
| 没有事实校验步骤 | 生成流水线只做概率预测，不检查"生成的对不对" | 编造的内容被当作事实输出 |
| 没有"不知道"状态 | 模型永远会生成文字，不会主动说"我不知道" | 即使训练数据中没有答案，也会生成一个"最像答案"的回答 |
| 无法区分"知道"和"生成" | 模型没有"这个信息我确信 / 这个我在猜"的区分能力 | 所有内容都以同样自信的语气输出 |

> 一句话：幻觉不可避免，因为模型永远会输出、不检查事实、不标注不确定--这三个特征是概率预测机制的结构性属性，不是调参数能消除的。

**关键认知**：

1. **根因是概率预测本质**：模型生成流水线中没有"事实校验"步骤，永远会输出文字，区别只在于碰巧对不对
2. **训练数据截止时间**：知识有训练时的时效边界，截止后的新事件模型不知道，但会自信地基于旧数据回答
3. **训练数据质量问题**：训练数据中的错误信息会被模型"学到"并当作事实复现
4. **长尾知识 ≠ 长尾 token**：长尾知识是冷门领域训练数据少导致先验弱（幻觉成因），长尾 token 是低概率词被选中（temperature 效果，非幻觉根因）
5. **prompt 措辞引导**：提问方式暗示模型"应该知道"（如"请详细介绍"），比开放式提问更容易诱发编造

> 一句话：幻觉的根因是概率预测没有事实校验，具体表现为数据截止、数据质量、长尾知识、prompt 引导五个层面--理解成因才能对症缓解。

### 本节记住五件事

1. 根因是概率预测本质：生成流水线没有事实校验步骤，模型永远会输出，"不知道"不是模型的状态
2. 训练数据截止时间：训练后的新事件模型不知道，但会自信地基于旧数据回答（如换了 CEO 仍报旧名字）
3. 训练数据质量问题：训练数据中的错误信息被模型"学到"并当作事实复现
4. 长尾知识 ≠ 长尾 token：前者是冷门领域训练数据少导致先验弱（幻觉成因），后者是低概率 token 被选中（temperature 效果）
5. prompt 措辞引导："请详细介绍"比"你知道吗"更容易诱发幻觉，提问方式本身会影响幻觉概率

## 实验记录：诱导并观察幻觉

> 产出脚本：`hallucination_experiment.py` · 模型：glm-5.2
> 目的：验证不同类型的问题能否诱导幻觉，观察模型幻觉时的表现特征，并测试提示词约束的缓解效果

### 实验设计

三类问题，每类分实验组（无 system prompt）和对照组（system prompt："如果你对用户提问不确定，请直接回答不知道"），共 6 次调用。temperature=0 保证可复现。

```text
虚构实体：问一个前提事实错误的问题
  "请介绍一下 2023 年诺贝尔文学奖得主村上春树的代表作"
  （实际 2023 年得主是 Jon Fosse，非村上春树）

冷门知识：问一个极其冷门的内部信息
  "引望公司研发管理部平台软件与MDC产品部的部长是谁"

过时信息：问一个训练截止后已有新答案的问题
  "DeepSeek最新发布的大模型是什么"
  （实际已发布 V4 系列，模型知识停留在 V3/R1）
```

### 实验结果

| 问题类型 | 实验组（无约束） | 对照组（提示词约束） | 是否幻觉 |
|---|---|---|---|
| 虚构实体 | 纠正前提错误（"2023 年得主是 Jon Fosse 非村上春树"），介绍村上真实作品 | 回答"不知道" | 均未幻觉 |
| 冷门知识 | 返回空内容 | 回答"不知道" | 均未幻觉 |
| 过时信息 | 回答 DeepSeek-V3（过时，语气自信） | 回答 DeepSeek-R1（过时，语气自信） | **均幻觉** |

### 结论

1. **虚构实体未幻觉--高频知识先验强**：模型对诺贝尔奖这类高频公开事件有强先验，能纠正用户的事实错误。验证了 Step 2 的概念：幻觉与否取决于训练数据密度，高频知识不易幻觉，长尾知识才易幻觉
2. **冷门知识未幻觉但返回空--推理模型的自我判断**：glm-5.2 作为推理模型，可能在思考阶段判断"我不知道"后选择不输出。说明推理模型在冷门问题上比非推理模型更不容易幻觉
3. **过时信息均幻觉--"提示词约束"对此类幻觉无效**：实验组和对照组都自信地返回了过时信息（V3/R1）。根本原因：模型**不知道自己过时**，不认为 V3/R1 是"不确定"的，它认为那就是事实。所以"不确定就说不知道"这条约束无法触发--模型没有"不确定"的感觉
4. **对照组的副作用--提示词约束是双刃剑**：虚构实体的对照组因为"不确定就说不知道"而拒绝了一个它本可以正确回答的问题（纠正前提 + 介绍作品）。提示词约束在减少幻觉的同时可能误伤正确回答
5. **对照组反而更"新"--system prompt 触发不同推理路径**：对照组提到 R1（2025 年 1 月），实验组只提到 V3（2024 年 12 月）。推测 system prompt 触发了不同的思考路径，但两者仍是过时信息，都属于幻觉

> 关键发现：提示词约束对"训练数据截止"型幻觉完全无效--因为模型不知道自己过时，不认为自己是"不确定"的。这类幻觉需要外部知识注入（RAG）才能解决，单纯靠 prompt 无法缓解。

## 缓解幻觉的思路

> 来源：概念 + 实验总结 · 目的：将缓解手段与幻觉成因做"对症下药"的对应，理解没有银弹

### 缓解手段与成因对应表

| 缓解手段 | 机制 | 对应的成因 | 实验验证 |
|---|---|---|---|
| **提示词约束** | system prompt 要求"不确定就说不知道" | prompt 措辞引导、长尾知识 | 对长尾知识有效（冷门知识对照组回答"不知道"），对过时信息无效（模型不认为自己是"不确定"的） |
| **降低 temperature** | 减少低概率 token 被选中的机会 | 概率预测本质（采样随机性） | 关联 Day 5 知识：低 temperature 让模型更"保守"，但不改变模型"知不知道" |
| **RAG（检索增强）** | 先检索外部知识库再生成，插入"事实校验"步骤 | 训练数据截止时间、长尾知识、训练数据质量 | 实验中"过时信息"幻觉正是 RAG 能解决而提示词约束不能解决的场景 |
| **结构化输出** | 要求模型给出引用来源或置信度标记 | 概率预测本质（无法区分知道和编造） | 让用户能识别"哪些是检索到的、哪些是模型推测的" |
| **多次采样投票** | 同一问题问多次，取多数一致答案 | 概率预测本质（采样随机性） | 代价是成本翻倍，且对"模型确信的错误答案"无效 |

### 提示词约束是双刃剑

实验中对照组的表现揭示了提示词约束的副作用：

```text
虚构实体对照组：
  问题："请介绍 2023 年诺贝尔文学奖得主村上春树的代表作"
  模型本可以：纠正前提（实际得主是 Jon Fosse）+ 介绍村上真实作品
  实际回答："不知道。"
  -> 提示词约束误伤了一个模型能正确回答的问题
```

| 策略 | 效果 | 代价 |
|---|---|---|
| 严格（"不确定就说不知道"） | 减少幻觉 | 误伤正确回答，损失有用性 |
| 宽松（"用你的知识回答"） | 保留有用性 | 模型不知道自己在编时仍会幻觉 |

### 为什么 RAG 比单纯调低 temperature 更能缓解幻觉

```text
temperature 解决的问题：
  采样阶段 -> 低概率 token 被选中 -> 减少采样随机性
  但：模型"不知道"的事实，temperature=0 也答不对

RAG 解决的问题：
  生成前 -> 插入外部知识检索 -> 绕过训练数据截止和长尾知识不足
  直接补上了生成流水线中缺失的"事实校验"步骤
```

> 一句话：temperature 调的是"怎么选"，RAG 补的是"拿什么选"--前者解决采样随机性，后者解决知识缺失，RAG 打在了根因上。

### RAG 的工作流程

RAG 在模型生成之前插入了一个"检索"环节，本质上是给模型"开卷考试"而非"闭卷考试"：

```text
离线阶段（提前构建知识库）：
  原始文档（PDF/Word/网页/数据库）
    ↓
  分块（chunking）：把长文档切成小段，每段几百 token
    ↓
  向量化（embedding）：用嵌入模型把每段文本转成向量
    ↓
  存入向量数据库（如 Chroma）

在线阶段（用户提问时）：
  用户提问"DeepSeek 最新发布的大模型是什么"
    ↓
  问题向量化：用同一个嵌入模型把问题也转成向量
    ↓
  相似度检索：在向量数据库中找与问题向量最接近的文档段落
    ↓
  拼接上下文：把检索到的段落 + 用户问题一起发给 LLM
    ↓
  LLM 基于检索到的真实信息生成回答（而非凭训练记忆猜）
```

**与传统查询的区别**：

| 对比维度 | 传统数据库查询 | RAG 检索 |
|---|---|---|
| 匹配方式 | 精确匹配（关键词 = 关键词） | 语义匹配（问题向量 ≈ 文档向量） |
| 能理解"意思"吗 | 不能（"最新大模型"和"V4 发布公告"关键词不匹配就查不到） | 能（向量距离近就能检索到，不要求措辞一致） |
| 输出 | 返回原始记录 | LLM 基于检索内容生成自然语言回答 |

**对应幻觉成因的解决**：

| RAG 环节 | 解决的成因 | 说明 |
|---|---|---|
| 知识库可随时更新 | 训练数据截止时间 | 知识库不受训练截止限制，新信息入库后立即可检索 |
| 知识库针对冷门领域构建 | 长尾知识 | 弥补训练数据不足，冷门领域也能检索到 |
| 知识库经过人工清洗 | 训练数据质量问题 | 入库前清洗，保证数据真实有效 |
| 检索到才回答 | 概率预测本质（没有事实校验） | "先查再答"替代"直接猜"，补上了事实校验步骤 |

> 一句话：RAG 的本质是给模型"开卷考试"--离线建库、在线检索、拼接上下文再生成，用外部真实知识替代模型过时的训练记忆。

### RAG 的设计矛盾：检索不到时怎么办

RAG 不是银弹，它把"幻觉还是不知道"的判断从模型内部转移到了系统设计层面：

```text
情况 1：RAG 有记录 -> 基于检索内容回答 -> 无幻觉 ✓
情况 2：RAG 没记录，但模型训练过 -> 严格策略说"不知道"（损失有用性）✗ / 宽松策略用模型知识（怎么确定不是在编？）✗
情况 3：RAG 没记录，模型也没训练过 -> 严格策略说"不知道"（正确）✓ / 宽松策略用模型知识（幻觉）✗
```

**核心矛盾**：无法在回答前判断当前是情况 2 还是情况 3--模型自己也不知道自己是"真知道"还是"在编"。

| 策略 | 做法 | 适用场景 |
|---|---|---|
| 严格模式 | 检索不到就说不知道 | 高风险领域（医疗/法律/金融），宁可不说也不能说错 |
| 混合模式 | 检索到用检索，检索不到用模型知识但标注"未经核实" | 通用助手，平衡有用性和准确性 |
| 路由模式 | 先判断问题类型：事实性/时效性问题走 RAG，通用知识问题直接让模型回答 | 复杂系统，需要额外分类逻辑 |

> 一句话：RAG 把"幻觉还是不知道"的难题从模型内部转移到了系统设计层面--由你决定"检索不到时该信任模型还是该拒绝回答"，这取决于业务场景对"说错"和"不说"哪个代价更大。

**关键认知**：

1. **没有银弹**：每种缓解手段只对特定成因有效，提示词约束对"过时信息"无效，temperature 不改变模型"知不知道"
2. **提示词约束是双刃剑**：减少幻觉但可能误伤正确回答（实验中虚构实体对照组就是例证）
3. **RAG 打在根因上**：在生成流水线中插入"事实校验"步骤，直接补上了概率预测缺失的环节
4. **RAG 的设计矛盾**：检索不到时，无法判断模型是"真知道"还是"在编"，需要根据业务场景选择严格/混合/路由策略
5. **对症下药**：不同成因用不同手段--数据截止用 RAG，采样随机性用低 temperature，prompt 引导用提示词约束

> 一句话：缓解幻觉的核心思路是"对症下药"--没有银弹，每种手段只解决特定成因，组合使用才能覆盖全面。

### 本节记住五件事

1. 五种缓解手段：提示词约束 / 降 temperature / RAG / 结构化输出 / 多次采样投票，各自只对特定成因有效
2. 提示词约束是双刃剑：减少幻觉但误伤正确回答（实验虚构实体对照组验证）
3. RAG 为什么最有效：在生成流水线中插入"事实校验"步骤，直接补上概率预测缺失的环节，解决训练截止和长尾知识问题
4. RAG 的设计矛盾：检索不到时无法判断模型"真知道"还是"在编"，需根据业务场景选严格/混合/路由策略
5. 对症下药：数据截止用 RAG，采样随机性用低 temperature，prompt 引导用提示词约束--组合使用才能覆盖全面
