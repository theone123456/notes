### Step 3 · LLMClient 结构设计（类型：思考）

**前置依赖**：Day 2 的 API 调用经验、Day 3 的消息角色概念

**做什么**：
- 规划 `LLMClient` 类的结构，确定属性和方法：
  - **属性**：
    - `api_key`：API 密钥（从环境变量或参数读取）
    - `base_url`：API 地址（支持 DeepSeek / 通义等兼容 OpenAI 格式的服务）
    - `model`：默认模型名
    - `messages`：对话历史列表（本日先预留，Day 8 实现）
  - **方法**：
    - `__init__`：读取 Key、初始化客户端
    - `chat`：发送消息并返回模型回复（本日只做单轮）
  - 后续将扩展的方法（本日不实现，但设计时预留思路）：
    - 多轮对话历史管理（Day 8）
    - `save` / `load` 历史持久化（Day 8）
    - 异常处理与重试（Day 9）
    - token 统计与成本估算（Day 10）
- 思考：API Key 应该硬编码在代码里还是从环境变量读取？为什么？

**检查点**：

### Step 4 · 搭建 LLMClient 骨架（类型：编码）

**前置依赖**：Step 3 的结构设计

**做什么**：
- 创建 `llm_client.py`，实现 `LLMClient` 类的骨架：
  - `__init__`：从环境变量读取 API Key（`os.getenv`），初始化 `openai.OpenAI` 客户端，设置 `base_url` 和默认 `model`
  - `chat` 方法：接收用户消息（str），构造 `messages` 数组（本日只含 system + user），调用 `client.chat.completions.create`，返回模型回复文本
- 在文件底部加 `if __name__ == "__main__"` 测试块：实例化 `LLMClient`，发一条消息，打印回复
- 运行验证：`python llm_client.py` 能成功返回模型回复
