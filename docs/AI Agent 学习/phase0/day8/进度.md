### Step 1 · 有状态的 Client 与持久化（类型：概念）

**前置依赖**：Day 3 的消息角色与多轮对话、Day 7 的 LLMClient 骨架

**做什么**：
- 回顾 Day 3 结论：API 是无状态的，每次请求都要传完整 `messages` 数组
- 理解今天要做的事：把"维护完整历史"的责任从调用方移到类内部（`chat` 从无状态变为有状态）
- 理解持久化：`self.messages` 存在内存里，进程退出即消失；要"接着聊"必须先落盘（序列化为 JSON 文件）
- 想清楚两个问题：
  1. 现在的 `llm_client.py` 里 `self.messages` 有没有被真正用起来？（提示：看 `chat` 方法，每次调用历史并没有累积）
  2. 为什么 JSON 适合存 `messages`？（列表 + 字典的标准序列化格式）

- Day 3 readme.md 的多轮对话节
- Python 官方文档：json 模块

**检查点**：
- 能说出"无状态 API"和"有状态 Client"的区别

### Step 2 · 改造 chat 方法，自动维护多轮历史（类型：编码）

**前置依赖**：Step 1、Day 7 的 llm_client.py

**做什么**：
- 先跑实验确认现状：连续调用两次 `chat`，第二次问"我刚才说了什么"，观察模型是否记得（预期：不记得，因为历史没进 `self.messages`）
- 改造 `chat`：
  - 把 user 消息 append 到 `self.messages`
  - 调用 API 时直接传 `self.messages`
  - 拿到回复后，把 assistant 消息也 append 到 `self.messages`，再返回文本
- 更新 `__main__` 测试块：连续两轮对话，第二轮验证记忆；可顺带打印 `len(self.messages)` 观察增长

**检查点**：
- 连续两次 `chat`，模型能正确复述第一轮的内容
- 能解释改造前后每次请求传的内容差别
- `self.messages` 长度随轮次增长（system + 2 × 轮数）

### Step 4 · 实现 save / load（类型：编码）

**前置依赖**：Step 3 的设计方案

**做什么**：
- 实现 `save`：把 `self.messages` 用 `json.dump` 写入文件，注意 `encoding="utf-8"` 和 `ensure_ascii=False`（保证中文可读）
- 实现 `load`：读取 JSON 并替换 `self.messages`；文件不存在时打印清晰提示、保留默认 system prompt，不抛异常
- 在 `__main__` 里补一段测试：`chat` 一轮 → `save` → 打开 JSON 文件肉眼检查格式

**检查点**：
- `save` 生成的 JSON 文件直接打开能看懂（每条消息有 role 和 content）
- `load` 之后 `self.messages` 与保存前完全一致
- 删掉文件再 `load`，程序不崩溃且提示清晰

**产出**：
- 文件：`llm_client.py` 更新（自写，写完贴给 AI review）
